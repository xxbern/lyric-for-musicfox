## 2. 核心性能基准 (P0 & P1 实现验证)

### 2.1 任务管理器测试表现
- **空闲与静止状态**（显示 `"......"` 占位符且无交互）：
  - **CPU 占用率**：恒定维持在 **0.0% ~ 0.1%**。
  - **原因**：主循环逻辑判定当前不处于滚动（`!playing` 且不超宽）和拖动状态，不申请任何重绘，主进程进入深度高能效休眠（直到后台接收到 UDP 音乐状态变化或鼠标滑过窗口由 OS 发送原生事件唤醒）。
- **跑马灯滚动播放状态**：
  - **CPU 占用率**：稳定维持在 **< 0.5%**（通常波动在 **0.1% ~ 0.3%**）。
  - **原因**：跑马灯更新仅在有效播放且超宽时启动重绘，并通过 `request_repaint_after(16ms)` (约 60FPS) 执行平滑推进，无 GPU/CPU 空转。
- **常驻内存 (Working Set)**：
  - **实测表现**：常态运行下，物理内存占用恒定在 **29MB ~ 37MB** 之间。
  - **原因**：去除了原先常驻的 `fontdb::Database` 大量全系统字体扫描结果，并在加载完所需字体切片后即时释放；默认不生成文件日志线程。

## 3. P2 & P3 待实施技术路线 (Dever 独立说明)

### 🟢 P2 阶段：歌词热重载全链路打通

#### 1. 系统托盘重载入口
- **目标文件**：`src/tray/windows_tray.rs` 和其 Stub `src/tray/stub.rs`。
- **实施改动**：
  - `TrayCmd` 增加 `ReloadLyrics` 枚举；
  - 构造菜单项增加【重载歌词】，点击时分发 `TrayCmd::ReloadLyrics`。
  - 主渲染循环中拦截该指令，原地调用 `load_config` 并通过 transient db 刷新 resolved font 样式。

#### 2. 设置界面 Pipe 通知与 Toast 生效
- **目标文件**：`src/settings/form.rs` 与 `src/settings/ui.rs`。
- **实施改动**：
  - 确保一键【保存并应用】完成时，后台线程成功执行 `crate::pipe::reload::notify_reload()` 触发共享管道改写；
  - UI 界面右下角无阻塞地弹出 Toast 确认并显示「配置已保存并已实时生效」（3秒）。
  - 管道线程唤醒：`windows_pipe.rs` 捕获到信号后，修改 `needs_reload`，并立刻调用全局 OnceLock `EGUI_CTX` 唤醒重绘。
