# lyric-for-musicfox 阶段三需求

> 平台：Windows 10 / 11 (x86_64)
> 语言 / 框架：Rust + Slint（歌词窗口 + 设置窗口统一 Slint；Windows 原生托盘与 Win32 API 仍按需使用）
> 上游文档：`docs/dev-stage-1/req.md`、`docs/dev-stage-2/req2.md`
> 参考脚本：`C:\Users\xx\.config\ahk\music_tray.ahk`（仅作为行为参考，不再依赖）

本阶段聚焦于「托盘交互修复」「设置 UI 视觉美化与输入调整」「设置功能全面检查与确认」以及「go-musicfox 集成」四大模块。所有 UI 控件描述均**与渲染框架无关**，落地到当前 Slint 实现时按具体 widget 类型映射（LineEdit / ComboBox / Button / CheckBox / Slider 等），框架替换不影响需求语义。

## 1. 托盘右键菜单高度限制

### 1.1 现状与问题

`tray-icon` 的菜单默认在鼠标右键按下位置弹出。Windows 屏幕高度有限（典型 1080p），当鼠标在屏幕底部（如右下角托盘图标）触发右键时，默认菜单会延伸到屏幕外，菜单底部被裁剪，看不到「退出」项。

### 1.2 需求

| # | 要求 |
|---|------|
| 1 | 右键托盘弹出菜单时，菜单整体的**最高 Y 坐标**（菜单顶部边界）**不超过当前鼠标光标的 Y 坐标**。即菜单只向下展开，永远不会向上越过鼠标。 |
| 2 | 该约束不改变菜单锚点的 X 轴行为（仍以鼠标 X 对齐）。 |
| 3 | 鼠标在屏幕任意 Y 位置按下右键，菜单顶部边界 ≤ 鼠标 Y，且菜单底部边界 ≤ 屏幕物理像素高度（不会出现菜单底部溢出屏幕底部）。 |
| 4 | X 仍以鼠标 X 对齐，Y 也以鼠标 Y 对齐（菜单在鼠标位置垂直起点向下展开）。 |

### 1.3 验收

- 在 1080p（1920×1080 物理像素）主显示器右下角托盘图标处右键：菜单全部可见，无截断。
- 在屏幕顶部（如 Y=50）右键：菜单从 Y=50 向下展开，仍完整可见（菜单高度 < 屏幕剩余高度）。
- 在屏幕中部任意 Y 坐标右键：菜单从该 Y 起向下展开，顶部不越过鼠标、底部不溢出屏幕。

## 2. 托盘 / 设置界面「重载」语义修复

### 2.1 现状

| 入口 | 行为 | 问题 |
|------|------|------|
| **托盘右键 → 重载歌词** | 主进程收到重载命令，调 `load_config` + 重建样式 + 唤醒渲染循环 | **正确**，保留 |
| **设置界面 → 🔄 重载歌词** | 仅调重载通知写命名管道，期望主进程接收到后重载 | **无效**：写管道本身既可能因主进程未运行而 connect 失败（信号丢失，无反馈），也可能运行但 reload 监听线程未触发样式重建；设置进程对重载失败无任何反馈，用户点击按钮后无视觉变化，主进程实际未重载 |

### 2.2 修复需求

| # | 要求 |
|---|------|
| 1 | 设置界面「重载歌词」按钮按下时，**复用**主进程已有的「重载」语义：调用 reload 管道通知主进程重载，明确这是「通知主进程重载」，并非本地操作。 |
| 2 | 当管道写入失败（如主进程未运行、connect 失败）时，按钮的 toast 文案必须**如实反馈失败原因**，例如「主进程未运行，无法重载（重启 lyric-for-musicfox 后生效）」，而不是「已发送重载通知」这种模糊表达。 |
| 3 | 写管道成功时 toast 维持「已发送重载通知」语义即可，但**不再使用**「配置已保存并已实时生效」这种描述（该描述仅适用于「保存并应用」按钮）。 |
| 4 | 主进程收到重载通知的语义**不变**（沿用 `docs/dev-stage-2/req2.md` §3.P2 的实现），无需改动管道监听与样式重建逻辑。 |
| 5 | 「保存并应用」按钮的行为不变：原子写 `config.toml` + 通知主进程重载 + 成功 toast「配置已保存并已实时生效」。 |
| 6 | 失败 toast 也维持与成功 toast 相同的展示时长（3 秒后自动消失），便于用户感知到按下按钮的反馈。 |

### 2.3 验收

| 场景 | 期望 toast |
|------|-----------|
| 主进程运行中，点击设置界面「重载歌词」 | 「已发送重载通知」 |
| 主进程未运行，点击设置界面「重载歌词」 | 「主进程未运行，无法重载（重启 lyric-for-musicfox 后生效）」 |
| 托盘右键「重载歌词」（主进程自身） | 主进程内直接调 `load_config` + 重建样式，不走管道；本地重载无 toast（托盘菜单无 toast 概念） |

## 4. 歌词调整预览

### 4.1 需求

| # | 要求 |
|---|------|
| 1 | 设置界面新增一个「歌词调整预览」区域，展示当前样式下的歌词渲染效果。 |
| 2 | 预览背景颜色固定为 `d4dce7`（RGB 212, 220, 231，即 `#d4dce7`），即使用户配置 `font_color = #ffffff`，预览仍能看清（白色文字在浅蓝灰背景上有足够对比）。 |
| 3 | 预览内容为「**天青色等烟雨**」（取自《青花瓷》开篇词，固定中文文本，便于视觉评估字号、字体、颜色、描边；中文长文本也能测试横向宽度估算）。 |
| 4 | 预览样式（字体 / 字号 / 加粗 / 斜体 / 颜色 / 描边）**实时跟随**当前表单字段，**不依赖**「保存并应用」。 |
| 5 | 预览区域**水平填满**设置窗口可用宽度；垂直高度固定约 80 DIP（与歌词窗口默认高度一致，便于直观对比）。**不使用**表单的 `width` / `height` 字段计算外框，避免输入框调整时预览区域跳动干扰评估。 |
| 6 | 预览位置在「🎨 歌词与样式」卡片**内部**底部（紧跟描边宽度之后），便于调整字体参数时立刻看到效果。 |
| 7 | 预览**不参与**磁盘序列化（不进入任何字段），**不触发**脏标记。调整预览样式本身不会让设置进程误判为「有未保存修改」。 |

### 4.2 样式字段

预览区域按当前表单中的以下字段实时渲染（语义与配置字段一致，不重复描述字段含义）：

- 字体族（family）
- 字号（pt）
- 加粗 / 斜体
- 字体颜色（解析 hex）
- 描边颜色 + 描边宽度（启用描边时）

预览的字体解析以「设置窗内可下拉选择的字体族集合」为限，与主进程的字体解析策略**保持一致**——主进程与设置进程共用同一份字体族解析入口，保证预览与最终渲染使用相同的 family 候选；不要求主进程专属字体特性（如字节加载的字形）在预览中可见。

### 4.3 验收

- 打开设置窗口，看到「天青色等烟雨」文字，背景为浅蓝灰色（`#d4dce7`）。
- 修改字号滑块 → 预览字号立即变化。
- 修改字体颜色 → 预览文字颜色立即变化。
- 修改加粗 / 斜体 / 描边颜色 / 描边宽度 → 预览样式实时跟随。
- 切换字体族下拉 → 预览字体立即变化（与下拉项保持一致）。
- 在预览框内**不修改任何字段** → 关闭设置窗口不应弹「未保存修改」对话框（验证 §4.1 第 7 条）。

## 5. go-musicfox WT 终端窗口托管

### 5.1 背景与目标

参考 `C:\Users\xx\.config\ahk\music_tray.ahk`（music_tray.ahk），原 AHK 脚本实现：

- 维护一个 Windows Terminal（`wt.exe`）窗口，运行 `go-musicfox` 命令行播放器，**脱离任务栏 + 工具窗口样式 + 禁用关闭按钮**。
- 安装 `SetWinEventHook` 监听目标窗口的最小化开始事件，**拦截**最小化：改为分层窗口透明隐藏（保留位置 / 大小，让 ConPTY 后台继续渲染）。
- 单击托盘图标：若 WT 已隐藏则恢复显示；若已显示则透明隐藏。

### 5.2 本阶段需求

| # | 要求 |
|---|------|
| 1 | 取消 music_tray.ahk 中独立的 lyric-for-musicfox.exe 启动逻辑（注释保留，**不再启动**）；保留 musicfox / WT 启动逻辑。 |
| 2 | 在 `lyric-for-musicfox.exe` 主进程内**内嵌** WT 窗口托管逻辑（**不依赖** AHK 脚本）：启动时确保存在一个运行 go-musicfox 的 WT 窗口；单击托盘图标切换显隐；WT 最小化时拦截为透明隐藏。 |
| 3 | **单击托盘**（而非双击）：若 WT 窗口不存在 → 启动；存在且当前隐藏 → 恢复显示并激活；存在且当前可见 → 透明隐藏。**不打开设置界面**（单击 = 切 WT，与原 AHK 一致；右键菜单「配置」项保留打开设置行为）。 |
| 4 | **最小化拦截**：监听 WT 窗口的最小化开始事件；事件触发时**在钩子线程外**（post-message 或 timer 排队）执行透明隐藏，避免钩子回调内直接操作窗口的不可重入问题。 |
| 5 | **WT 样式**：启动后应用工具窗口样式（脱离任务栏）+ 分层窗口样式（用于 alpha 透明），移除标题栏与系统菜单，禁用系统菜单的「关闭」项。 |
| 6 | **隐藏 / 恢复**：用分层窗口 alpha 实现。alpha=0 = 隐藏，alpha=255 = 显示。**不**用 `ShowWindow(SW_HIDE)`——保留 SHOWNORMAL 状态让 ConPTY 持续渲染。 |
| 7 | **去最小化按钮 / 最大化按钮**：移除最小化与最大化按钮，连同禁用关闭按钮一起在 WT 启动后一次性设置（与原 AHK 一致）。 |
| 8 | **退出时清理**：主进程退出（托盘右键「退出」或进程退出 hook）时 → 通知 WT 窗口关闭（**不强制杀进程**，让 go-musicfox 自然退出）；同时清理事件钩子。 |

### 5.3 进程启动顺序

| 时机 | 行为 |
|------|------|
| 主进程（lyric-for-musicfox.exe）启动 | **不启动** go-musicfox / WT（由用户在主进程已运行时单击托盘触发 §5.4 启动，或独立启动 WT） |
| 主进程启动 +1s | 如果 WT 已存在则应用 WT 样式（脱离任务栏、无法关闭、最小化拦截）并安装事件钩子 |
| 单击托盘 | 见 §5.4 |
| 退出主进程 | 见 §5.2 第 8 条 |

### 5.4 单击托盘逻辑

按以下顺序执行（每步独立，便于单步验证）：

1. 按标题（如 `MusicFoxTerminal`）+ 进程名（`WindowsTerminal.exe`）查找现有 WT 窗口。
2. 若未找到 → 启动 WT：执行 `wt.exe -w new -d "<AppDir>" --title "<Title>" "<MusicfoxPath>"`；1 秒后应用样式 + 安装事件钩子；返回。
3. 若找到且当前为隐藏态（alpha=0）→ 恢复显示（alpha=255）+ 置前激活。
4. 若找到且当前为可见态（alpha=255）→ 透明隐藏（alpha=0），不改变窗口位置 / 大小。

### 5.5 配置字段

新增 `wt` 配置节（或并入 `system`，视实现便利而定）：

| 字段 | 类型 | 默认值 | 校验 |
|------|------|--------|------|
| `wt_musicfox_path` | `String` | `C:\Users\xx\app\musicfox\musicfox.exe`（与原 AHK 一致） | 文件存在则通过；不存在则保存时红字提示「go-musicfox 可执行文件不存在」 |
| `wt_app_dir` | `String` | `C:\Users\xx\app` | 目录存在则通过；不存在 → 红字提示 |
| `wt_title` | `String` | `MusicFoxTerminal` | 非空字符串 |

> `wt_app_dir` 与 `wt_musicfox_path` 都暴露为可配置字段，避免硬编码用户实际路径。
> 字段缺失策略：按 `docs/dev-stage-1/req.md` §12.1，缺失走 `Default::default()`。

### 5.6 验收

| 场景 | 期望 |
|------|------|
| 主进程启动后 WT 不存在 | 静默；不动 WT |
| 主进程启动时 WT 已存在 | 1s 后自动应用样式（脱离任务栏、无法关闭、最小化拦截） |
| 单击托盘（WT 存在且可见） | WT 变为完全透明（视觉上消失）；go-musicfox 仍运行；位置 / 大小不变 |
| 单击托盘（WT 已隐藏） | WT 恢复可见 + 置前；ConPTY 状态保留 |
| 用户最小化 WT 窗口 | 立即拦截为透明隐藏（不进入最小化态、不进入任务栏） |
| 右键托盘 → 退出 | WT 窗口关闭；go-musicfox 进程自然退出；钩子清理 |

## 6. 设置界面新增 go-musicfox 配置

### 6.1 背景

承接 §5：WT 启动依赖 `musicfox.exe` 路径（`wt_musicfox_path`）。本节要求在设置界面暴露**单个**配置（`wt_musicfox_path`） + 一个打开 go-musicfox 数据目录的便捷按钮（cookie / db 等用户数据所在目录）。`wt_app_dir` 等其他字段仍按 §5.5 默认值存在，**不暴露**到 UI。

> **go-musicfox 数据目录解析（核心区分）**：根据 go-musicfox 源码 `utils/app/app.go`，数据文件（cookie、db、logo.png 等）存储在 `DataDir()` 下，与 `ConfigDir()`（config.toml 所在）**未必是同一个目录**。具体取决于模式：
>
> | 模式 | `ConfigDir`（config.toml） | `DataDir`（cookie、db） |
> |------|--------------------------|-------------------------|
> | **portable**（`MUSICFOX_ROOT` 非空） | `<MUSICFOX_ROOT>` | `<MUSICFOX_ROOT>/data` |
> | **XDG**（未设 MUSICFOX_ROOT） | `<XDG_CONFIG_HOME>\go-musicfox` | `<XDG_DATA_HOME>\go-musicfox` |
> | **Windows 默认**（未设 XDG_*） | `%LOCALAPPDATA%\go-musicfox` | `%LOCALAPPDATA%\go-musicfox` |
>
> **Windows 特别注意**：默认情况下，`ConfigDir` 和 `DataDir` **都是 `%LOCALAPPDATA%\go-musicfox`（不是 %APPDATA% / Roaming）**；cookie 与 config.toml 在同一目录下。但 portable 模式下两者分裂，cookie 在 `<ROOT>\data\cookie`，与 config.toml 不同路径。
>
> **「打开 go-musicfox 数据目录」按钮 = 打开 `DataDir()`**（cookie、db、logo.png 所在目录），不打开 `ConfigDir()`。这与 `wt_musicfox_path`（exe 路径）无关。

### 6.2 需求

| # | 要求 |
|---|------|
| 1 | 设置界面新增一个「🎵 go-musicfox」卡片（与现有「🪟 窗口与定位」「🎨 歌词与样式」「⚙️ 系统与网络」并列），放置在「系统与网络」卡片**之后**。 |
| 2 | 卡片内仅暴露一个可编辑字段：<br>- **go-musicfox 可执行文件路径**：显示并可编辑 `wt_musicfox_path`。使用单行文本框（占满剩余宽度）+ 右侧「浏览…」按钮（点击后弹原生文件选择对话框，让用户选 `.exe` 文件；选完自动填入路径字段）。 |
| 3 | 字段下方提供校验错误红字（沿用现有 `field_errors` 机制）：路径不存在 → 红字「路径不存在」；空字符串 → 红字「不能为空」。 |
| 4 | **「打开 go-musicfox 数据目录」按钮**：点击后调 `explorer.exe` 打开 `DataDir()`（cookie / db / logo.png 等用户数据所在）。**与 `wt_musicfox_path`（exe 路径）无关**。具体实现（4 级 fallback、`ConfigDir` 与 `DataDir` 区分、错误 toast）详见 §6.3。简述：<br>- `MUSICFOX_ROOT` 非空 → 打开 `<MUSICFOX_ROOT>/data`（注意**不是** MUSICFOX_ROOT 本身，cookie 不在那里）<br>- 否则 `XDG_DATA_HOME` 非空 → 打开 `<XDG_DATA_HOME>\go-musicfox`<br>- 否则 Windows `%LOCALAPPDATA%\go-musicfox`（优先 `LOCALAPPDATA`）<br>- 否则 `%USERPROFILE%\AppData\Local\go-musicfox`（兑底） |
| 5 | 「浏览…」按钮依赖原生文件选择对话框（与 Rust File Dialogs 等价）。 |
| 6 | 字段保存走现有表单流程（标记脏 + 防抖 500ms + 保存时原子写）。`wt_musicfox_path` 随其他字段一并落入 `config.toml`。 |
| 7 | 修改 `wt_musicfox_path` 不影响主进程正在运行的 WT 状态——**仅在下次启动 WT 时生效**（下次单击托盘、WT 不存在时按新路径启动）。在 WT 已运行期间修改路径 → 保存后不重启 WT（避免打断 ConPTY）；但**下次**单击托盘若 WT 已被关闭则按新路径启动。 |
| 8 | 「打开配置文件夹」按钮（指向 `%APPDATA%/lyric-for-musicfox/`）保留原行为，新按钮独立命名「打开 go-musicfox 数据目录」以避免混淆。 |
| 9 | 按钮右侧显示当前解析出的**实际目录**（灰色小字、只读），让用户提前知道按钮会打开哪里。例：`当前：%LOCALAPPDATA%\go-musicfox`。 |

### 6.3 go-musicfox 目录解析规则

按钮「打开 go-musicfox 数据目录」需要解析两个目录，复刻 go-musicfox 源码 `utils/app/app.go` 中 `ConfigDir()` / `DataDir()` 的语义：

**`ConfigDir()`（config.toml 所在，**本节 UI 不直接使用**，仅供解析逻辑理解）**

| 优先级 | 条件 | 路径 |
|--------|------|------|
| 1 | `MUSICFOX_ROOT` 非空 | `<MUSICFOX_ROOT>` |
| 2 | `XDG_CONFIG_HOME` 非空 | `<XDG_CONFIG_HOME>\go-musicfox` |
| 3（Windows 默认） | `LOCALAPPDATA` 存在 | `%LOCALAPPDATA%\go-musicfox` |
| 4（Windows 兑底） | `USERPROFILE` 存在 | `%USERPROFILE%\AppData\Local\go-musicfox` |

**`DataDir()`（按钮真正打开的目标，cookie / db / logo.png 所在）**

| 优先级 | 条件 | 路径 |
|--------|------|------|
| 1 | `MUSICFOX_ROOT` 非空 | `<MUSICFOX_ROOT>/data`（**注意是 data 子目录**，cookie 不在 MUSICFOX_ROOT 本身） |
| 2 | `XDG_DATA_HOME` 非空 | `<XDG_DATA_HOME>\go-musicfox` |
| 3（Windows 默认） | `LOCALAPPDATA` 存在 | `%LOCALAPPDATA%\go-musicfox` |
| 4（Windows 兑底） | `USERPROFILE` 存在 | `%USERPROFILE%\AppData\Local\go-musicfox` |

**按钮行为**：

- `DataDir()` 解析成功且目录存在 → 启动 `explorer.exe <dir>` 打开该目录。
- `DataDir()` 解析成功但目录不存在 → 仍按上述路径启动 `explorer.exe`（Windows 资源管理器允许打开不存在的目录，会显示「找不到该项目」提示；与原 AHK 行为一致）；按钮右侧的「当前：...」提示不变（提示「启动 go-musicfox 后会自动创建」）。
- `DataDir()` 解析失败（所有环境变量都缺失）→ toast「无法定位 go-musicfox 数据目录」3 秒消失；`explorer.exe` 不启动。
- 按钮右侧的「当前：...」灰色提示**始终显示**解析结果（即使目录不存在也显示），让用户提前预知按钮会打开哪里。

### 6.4 字段落盘示例

```toml
[wt]
musicfox_path = "C:\\Users\\xx\\app\\musicfox\\musicfox.exe"
app_dir = "C:\\Users\\xx\\app"
title = "MusicFoxTerminal"
```

> `[wt]` section 含 §5.5 表格中三个字段；其中仅 `musicfox_path` 暴露到设置 UI（`app_dir` / `title` 保持代码默认，不让用户在 UI 改动，避免误改后 WT 找不到窗口）。`wt_title` 在代码中以 `Default::default()` 形式存在即可。

## 7. 设置界面视觉现代化与美化

### 7.1 背景与现状

从原 egui 迁移至 Slint 后，当前设置界面由于缺少视觉层级与容器设计，整体表现较为简陋：表单项平铺在单色背景上，各区域无卡片容器分隔，按钮与弹窗风格生硬。本节针对 Slint 渲染特性，确立**现代 Fluent / 极简卡片化**的视觉规范。

### 7.2 视觉规范与卡片化需求

| # | 视觉模块 | 规范与要求 |
|---|---|---|
| 1 | **整体背景与层级** | 窗口背景统一采用柔和中性浅色调（如浅灰背景），与卡片形成清晰对比；各卡片采用纯白底色（`#ffffff`）+ 统一圆角（6~8px）+ 细腻浅色微边框（如 `#e5e7eb` 或 `#d1d5db`）包裹，消除杂乱平铺感。 |
| 2 | **卡片容器（Grouped Cards）** | 界面分为四个独立卡片：<br>① `🪟 窗口与定位`<br>② `🎨 歌词与样式`<br>③ `⚙️ 系统与网络`<br>④ `🎵 go-musicfox`<br>卡片内边距规范统一（12~16px），卡片间保持适度间距（12~16px），提供呼吸感。 |
| 3 | **表单排版与对齐** | 严格规范左侧标签宽度（如固定 90~100px 并垂直居中对齐）；输入框、滑块、下拉框、复选框在卡片内自适应填充并对齐，消除各行控件宽窄不一的视觉跳跃感。 |
| 4 | **底部操作栏美化** | 底部操作栏固定悬浮，顶部分割线清晰；主操作按钮「💾 保存并应用」采用**主色高亮**（Accent Primary），次要按钮（「🔄 重载歌词」「📁 打开配置目录」）采用中性次级按钮样式；右侧错误提示红字自适应截断并垂直居中。 |
| 5 | **模态对话框美化** | 「配置解析失败」与「未保存修改」确认弹窗采用半透明暗黑遮罩（带景深感）+ 白色居中卡片（大圆角 8~12px + 柔和阴影/边框）；对话框内标题、正文、主/次/取消操作按钮布局清晰对齐。 |
| 6 | **Toast 浮动通知美化** | Toast 悬浮于右下角，采用深色半透明圆角矩形（或现代深灰黑胶囊样式），内嵌文字水平垂直居中，具备自适应文本宽度与平滑展示效果。 |

### 7.3 验收

- 打开设置窗口，界面具备明显的浅色底色与白色卡片层级，无大面积粗糙留白或元素挤压。
- 四个配置卡片圆角与微边框统一，视觉风格干净现代。
- 底部操作栏主次按钮分明，保存按钮在视觉上具有首要操作引导性。
- 弹窗与 Toast 风格精致，无粗糙白框与生硬突兀感。
