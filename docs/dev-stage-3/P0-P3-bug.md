## 2. 问题根因深度技术分析

### 🔍 BUG-01: 右键托盘菜单位置高于鼠标
- **根因剖析**：
  - 当前代码使用了 `tray-icon` crate 的 `TrayIconBuilder::new().with_menu(Box::new(menu))` 机制。
  - 在 Windows 平台，`with_menu` 会将菜单完全托管给 `tray-icon` 内部的 Windows 消息循环（WndProc）。当收到系统右键消息时，库内部直接调用默认参数的 `TrackPopupMenuEx`，系统默认以鼠标为基准向右上方或右下方居中展开，从而绕过了我们在应用层设置的 Y 轴约束。
- **修复对策**：
  - 不使用 `with_menu` 自动托管，改为在 `TrayIconEvent` 接收到 `Right` 点击时，由主进程/平台层通过 Win32 API 原生调用 `TrackPopupMenuEx`，传入 `TPM_TOPALIGN` 并显式传入经过校验的 `(cursor_x, cursor_y)` 坐标，确保菜单 100% 仅向下展开。

---

### 🔍 BUG-02: 左键托盘效果和右键一样（弹出菜单）
- **根因剖析**：
  - 同样是因为使用了 `TrayIconBuilder::with_menu(Box::new(menu))`。
  - 在 Windows Shell 的通知区域（Shell_NotifyIcon）机制下，当托盘图标绑定了原生 HMENU 句柄时，Windows 系统的某些事件机制（或 `tray-icon` 库内部处理 `WM_LBUTTONUP` 时）会自动激活上下文菜单，导致左键单击事件被拦截或直接触发了弹出菜单，无法稳定分发 `TrayCmd::ToggleWt`。
- **修复对策**：
  - 将菜单与托盘对象解耦（移除 `with_menu`），由 Rust 显式监听 `TrayIconEvent::Click`：
    - `MouseButton::Left` → 仅发送 `TrayCmd::ToggleWt`（调起/显隐 WT）；
    - `MouseButton::Right` → 触发受控 Y 坐标的右键菜单。

---

### 🔍 BUG-03: 托盘菜单中的 go-musicfox 响应时序与冗余
- **根因剖析**：
  - 首次点击时，WT 尚未启动，代码执行了 `launch_wt` 异步启动进程，但因为进程启动需要约数百毫秒，导致首次点击未能立即激活前台窗口；第二次点击时由于窗口已存在才执行了 `ShowWT`；
  - 菜单项与左键功能重复，增加了用户心智负担。
- **修复对策**：
  - 按用户需求彻底移除右键菜单中的「🎵 go-musicfox」项，精简为【配置】、【重载歌词】、【退出】三个核心项；
  - WT 的唤起与显隐完全交给托盘左键，并在启动时优化窗口查找与置顶激活逻辑。

---

### 🔍 BUG-04: 设置界面样式细节问题
- **根因剖析**：
  1. **输入框高度过高**：Slint Material 3 规范中的 `LineEdit` 默认适配触控目标（高度约 48px），在桌面紧凑表单中显得过于庞大。未显式设置 `height: 32px;`。
  2. **出现滚动条**：外层包裹了 `ScrollView`，由于内边距和各卡片元素高度累加，导致内容高度略微超过窗口可视区域，触发了滚动条。
  3. **端口输入框与描述冗余**：端口本身不可在界面热修改，使用禁用的 `LineEdit` 和下方长文本说明显得杂乱。
  4. **缺少颜色选择能力**：目前仅有十六进制文本框，用户无法直接点击拾取颜色。
- **修复对策**：
  1. **输入框紧凑化**：为尺寸（宽/高）、位置（X/Y）、描边宽度、颜色等输入框统一显式指定紧凑高度（`height: 32px;`）。
  2. **消除滚动条**：调整窗口整体高度（如 680px）与各卡片间距（10px），移除外层 `ScrollView`，改为自然流式布局，保证 100% 无滚动条。
  3. **端口纯文本化**：接收/发送端口改为只读 `Text` 标签并排展示（如 `Text { text: "接收: " + root.recv-port-text + "  |  发送: " + root.send-port-text; }`），移除下方灰色长描述。
  4. **增加常用预设颜色色块选择器**：在字体颜色行提供常用调色板色块（纯白、亮黄、青绿、天蓝、粉红、亮橙、淡紫），点击色块即时填入对应 Hex，并提供当前颜色实时色块预览。
